# A second native source backend

Native file preparation previously selected Lean even though the shared compiler,
search, assessment, repair and source-publication owners already retained typed
backend outputs. The host now registers a finite-transition implementation for
`.contract.json` alongside Lean. Selecting such a file in the existing explorer
prepares its complete source graph, actual Z3 observations and English readings.
The viewer and authority kernel acquire no finite-specific branch or AST.

The [validation record](../../results/native-finite-source-20261125.json) retains
exact executables, checks, observations and limits. This is a production native
source integration of the existing bounded finite format, not an arbitrary
SMT-LIB, RTL or native-code frontend.

## Original data and separate roles

| Role               | Implementation       | Original retained data                                                          |
| ------------------ | -------------------- | ------------------------------------------------------------------------------- |
| Compiler           | `finite.transition`  | Complete contract/model source and typed finite AST                             |
| Search             | `finite.z3`          | Complete property set, actual confined Z3 and independently evaluated witnesses |
| Meaning renderer   | `finite.english`     | Deterministic readings of typed unsigned expressions                            |
| Native preparation | Host suffix registry | Original implementation paired with its typed snapshot through repair           |

The finite data decoder is separated from solver execution/settings. Compilation,
search and rendering use the existing distinct content-addressed artifact domains;
the compiler checks complete current source bytes before checked cache restoration.
Search reports bind their original compiler observation and method. Readings cannot
replace expressions, source or search results. A warm preparation still checks
current inputs and resources; it does not execute another solver or generate new
English. Source changes require new observations. Corrupt or misbound cache bodies
cannot be reused as a successful prefix.

Each original property receives a real Z3 query and an independent complete finite
enumeration. Both must agree. The observational API returns only a typed witness or
absence observation, never `Checked`, files for evidence admission or a receipt.
Malformed/unknown output, disagreement, nonzero exit, interruption, output limits
and changed resources fail without an admitted observation. The existing verifier
continues to construct checked artifacts through its separate unchanged evidence
workflow.

The format retains its existing limits: unsigned width 1–8, at most 16 total input
bits, 1–16 properties, bounded terms and 64 KiB per finite data file. Source readers
keep their separate larger budgets. The model path is normalized and relative to
the workspace, not the contract's containing directory. Host-selected public Z3
and the original worker/resources remain independently bound. A JSON source cannot
select an executable, shell command, network request or new grant.

## The same public source/repair journey

Properties and assignments are navigable declarations with exact original JSON
value-start lines, including escaped keys and repeated strings elsewhere. Edges
connect properties to the output assignments they actually reference. All graph
proof hints remain unknown; a negative search does not become project evidence.
Pure JSON navigation adds file headers to the project map without solver work.
Unchanged Lean/Rust navigation keeps its original cache namespace.

The GUI uses its existing file tabs, source/graph split, info display, model review,
Finding and exact-patch review. The same opaque native owner retains the original
finite preparation through source edits and reanalysis, preserving the user's
independently held requirement. Returning to a retained tab does not inspect the
file again. Restart requires fresh processor approval and revalidates inputs
before complete-cache reuse. Missing dependencies fail beside readable source;
selecting an existing valid file recovers without hidden configuration edits.

The public TUI now uses `/graph FILE` for registered compiled views. `/graph` with
no argument retains configured Lean root discovery. `/lean-prepare` is the explicit
Lean library setup operation; the former `/atlas` commands have no aliases.
A finite workspace can select `--verifier z3.finite.v1` at startup to avoid preparing
the unrelated default Lean verifier. Source graph selection and accepted-project
verification remain separate responsibilities.

The shared blind-translation prompt now accepts backend-owned formal domains and
preserves their explicit arithmetic/evaluation rules. Its engine identity advances
to `meden-claimcheck-roundtrip-v2`; old assessments keep their original identity.
Finite context contains formal terms, width and simultaneous modular semantics,
without authored descriptions or prepared English/search observations.

## Validation and limits

The real-tool production-owner test covers an actual overflow witness, exact
complete source projection, cache reuse without new search/render events, reviewed
model repair and reanalysis without changing the requirement or admitting evidence.
Runtime faults separately exercise disagreement, malformed output, unknown results,
real started-solver timeout/cancellation and changed resources. Pure tests cover
lazy/ambiguous registration, structural JSON positions and deterministic rendering.
The architecture guard also refuses finite ASTs in shared/native retention.

The required public TUI journey uses actual offline Z3 without Lean or model
approval, recovers by selecting an existing file and reopens the original graph.
The native browser journey follows explorer selection, completed observations,
source-line navigation, cross-file tabs, explicit model approval, exact patch
review, real repaired searches and cached restart. Inference in those gates is
scripted; it is not live-model quality evidence.

The sealed candidate passes 361 Rust unit/integration/doc checks, 55 architecture
checks, 15 focused Python checks and all 37 required TUI journeys. The initial
81-case GUI run passes all 80 existing cases; the new finite repair reaches its
comparison but exceeds the default five-second DOM assertion under concurrent
real-tool work. Only that new case receives explicit operation-completion waits
and passes a focused rerun. No performance threshold is relaxed. Decoded TUI
failure/recovery/restart screens and the new source/reopened browser screens are
inspected. These results retain the initial failure rather than replacing its
record with the rerun. Serialized retained-tab checks pass in both motion settings:
29.3 ms p95 with reduced motion and 28.5 ms with normal motion, below the
unchanged 250 ms two-animation-callback budget. This scheduling proxy does not
measure physical paint or establish a paired speedup.

In the focused browser observation, first preparation takes 4.035 s and cached
restart takes 2.980 s to prepared status. The warm finite preparation span is
1.165 s, including 86 ms in complete source decoding/capture; native binding and
view materialization take 0.432 ms and 1.215 ms. No compile, solver-search or
English-rendering event runs on that restart. These are functional desktop
observations, not a controlled speedup, first-graph paint or field percentile.
The [separate event audit](event-latency-current.md) records the actual Lean-project
interaction stalls and native validation waits that still need improvement.

After deployment, public explorer/node navigation in both actual projects retains
the complete original source, reader, inventory, navigation and evidence views,
conversations and candidates. Both reuse the exact original semantic artifacts
and finish idle without model approval. Riemann reaches prepared status in
21.209 s (Lake query 9.769 s, input fingerprint 6.775 s); EthLib takes 3.234 s.
These unpaired functional observations confirm that native validation waits
remain; they do not establish an improvement over the earlier event captures.
All 88 served frontend assets remain byte-identical.

A separate explicitly approved Ollama Cloud `minimax-m3` trial of the generalized
meaning prompt stopped on its first request with HTTP 429 (provider usage/rate
limit). No translation, repair or independent-check success is claimed for that
trial. It retains the original source and failure record; no automatic retry,
account rotation or credential fallback was performed. This leaves live validation
of the new prompt unavailable, while local conformance work remains independently
verifiable.

No new core/agent authority transitions or extracted refinement are claimed. Tool
execution, source/resource attribution, serialization and OS behavior remain
adapters. Generic layout/collection and navigation-annotation ownership, the
measured browser/native waits and the final retirement audit remain open in the
[original migration plan](../architecture/typed-core-and-plugins.md).
