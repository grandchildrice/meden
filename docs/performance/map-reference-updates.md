# Retaining the project-map reference universe

The [validation record](../../results/map-reference-updates-20261125.json)
retains complete comparisons, capture metadata and the public gates.

The [event audit](event-audit-20261125.md) found repeated global reference work
when small detail responses arrived over EthLib's 42,857 declaration headings.
The scene now retains one candidate universe while ordered declaration IDs,
names, files and visibility remain unchanged. New reference arrays resolve
against that universe. A changed candidate replaces the index and all retained
readings; another inventory never inherits an old index.

There is one runtime resolver. Its former one-shot function is replaced by the
structural `ReferenceIndex`; its target tables retain IDs instead of old source
or semantic objects. Source readings use weak array keys bound to the exact
file and namespace. Namespace lookup/miss tables are temporary per resolution,
so arbitrary future reference strings cannot accumulate in an everlasting miss
table. Output keeps original Map order, namespace search, private visibility,
ambiguity, fallback, cycles, self suppression and global ordered deduplication.
Role-only updates retain their edges. No worker, renderer, dependency, compiler
resource, native wire format or evidence authority is added.

The actual scene owner compares only changed files before deciding whether the
candidate universe changed. It still materializes current symbol values and
ordered edges. Reusing indices does not replace the original input, version or
generation checks. Inputs remain immutable observations, as required by the
existing scene/navigation owners; the cache is an optimization, not authority
or a new JavaScript/refinement proof.

## Same-process actual-project comparison

Four fresh-browser captures first recorded the unchanged deployed GUI: two per
actual project, ordinary motion and matching hidden source maps. An independent
copy of the original production modules is retained privately as the measured
counterfactual. Original served inventories and the detail paths/bodies from the
first captured drill feed both implementations over identical geometry. After
every arrival, complete descriptions, symbols, pins and ordered edges match.
Inputs are unchanged. Nine alternating sequences exclude initial scene creation,
decoding and equality checks from the timed update interval.

## Regression contract

The generated update traces now include unchanged identities with new reference
arrays, renamed candidates, private/public changes, cached misses and shared
arrays. Every step matches both a fresh full scene and the independent original
array/filter resolver, while earlier scenes stay unchanged. Explicit cases cover
same-array cross-file/namespace reuse, self suppression, empty IDs, global
delimiter collisions and candidate additions/removals/ambiguity. The independent
oracle is shared only by tests, with no production fallback.

The paired performance gate times eight small detail arrivals over 38,400 fixed
headings, with a fresh prepared scene per sequence and nine interleaved pairs.
Forcing global-index reconstruction retains identical complete output but must
fail the 0.65 median ratio budget. This is separate from the older reference
lookup and geometry budgets. `npm run test:fuzz` runs 3,000 adversarial update
traces; `npm run test:performance` includes this new gate.

The public small-map journey also changes a target's private/public visibility
while the referring file remains unchanged and cached. It observes the new
inventory, disappearance/reappearance of the reference, zero rereads of that
source, quiet chat and no compilation, then restarts unapproved. Its existing
transfer failure/retry and late-former-body checks remain. This checks the actual
navigation cache boundary rather than forcing a redundant HTTP read.
