## Reuse published semantic-assessment tools

The user's updated direction is to reuse public semantic-gap evaluation tools;
`docs2formalspec` is not presented as the chosen semantic-check engine in the UI.

- **[claimcheck paper](https://arxiv.org/abs/2610.17358), [public code](https://github.com/metareflection/claimcheck):** translate a formal claim back to natural language without showing the original requirement, then use a separate comparison judge. The paper evaluates 3,234 cases across four languages, including Lean, reporting 8.2–9.8 macro-recall points over its direct-comparison baseline. The public CLI README emphasizes Dafny; a Lean production adapter still needs implementation and validation.
- **[FormalAlign paper](https://arxiv.org/abs/2410.10135), [public code](https://github.com/rookie-joe/FormalAlign):** a trained alignment model scores informal/formal pairs. The reported Alignment-Selection Scores vary substantially: 99.21 on FormL4-Basic and 66.39 on MiniF2F-Valid. These are benchmark selection scores, not a universal defect-detection rate or Meden's measured accuracy.

At the original UI review these were connection candidates. The later native
adapter runs claimcheck-derived two-pass requests and a pinned selected-module
Lean Atlas extraction core; see [native usage and scope](../gui.md).
The recorded demo remains a simulation with archived source/evidence.
The info popover explains the comparison in ordinary Japanese and links to the
public tools. NG/OK results remain explicit UI examples. Threshold calibration and broader evaluation on software specifications remain
open engineering work; no percentage is fabricated for this prototype.
